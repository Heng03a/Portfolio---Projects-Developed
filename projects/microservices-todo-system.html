Full-Stack Microservices Todo Platform

This project is a containerized full-stack microservices platform built using Angular, Node.js, Express, Docker Compose, and AWS DynamoDB Local.

The system was designed to simulate modern distributed application architecture principles commonly used in cloud-native enterprise environments, including service separation, container orchestration, RESTful communication, and infrastructure isolation.

Project Objectives

The goal of this project was to move beyond a traditional CRUD application by implementing a more realistic multi-service architecture involving:

  • Frontend and backend service separation
  • Containerized backend infrastructure
  • NoSQL database integration using DynamoDB
  • Docker Compose orchestration
  • JWT-based authentication flow
  • Monorepo project structure
  • Environment-based configuration management

Frontend Architecture

The frontend application was developed using Angular as a Single Page Application (SPA) architecture.

Angular services were used to communicate with backend REST APIs through structured HTTP requests, while route guards and JWT token interception were implemented to secure protected application routes.

The frontend also includes:

  • Responsive UI design
  • Task management workflow
  • Authentication screens
  • Protected navigation routes
  • Service-based API integration
  • Cross-browser compatible layouts

Backend Architecture

The backend service was built using Node.js and Express.js following RESTful API design principles.

The backend exposes APIs for:

  • User authentication
  • Todo item creation
  • Todo retrieval
  • Task updates
  • Task deletion

JWT authentication was implemented to secure protected API endpoints and validate authenticated requests.

DynamoDB Integration

Instead of using a traditional relational database, this project integrates AWS DynamoDB Local using AWS SDK v3 to demonstrate NoSQL database architecture concepts.

DynamoDB runs as an isolated Docker container and communicates internally with the backend service through Docker networking.

The backend includes retry logic and automated table initialization to handle service startup timing dependencies during container orchestration.

Docker & Infrastructure Orchestration

One of the key engineering focuses of this project was infrastructure orchestration using Docker Compose.

The system was restructured into a monorepo architecture with centralized infrastructure management, allowing Docker Compose to orchestrate:

  • Backend API container
  • DynamoDB Local container
  • Persistent Docker volume storage
  • Internal container networking
  • Environment variable configuration

This setup simulates production-style infrastructure coordination and demonstrates understanding of service isolation and container lifecycle management.

Engineering Challenges

Several engineering challenges were encountered and resolved during the development process:

  • Resolving Docker container naming conflicts during orchestration restructuring
  • Converting frontend Git submodule architecture into a proper monorepo structure
  • Implementing retry logic for delayed DynamoDB container readiness
  • Managing Docker persistent volumes for database storage
  • Configuring environment-based infrastructure variables
  • Handling frontend/backend distributed communication architecture

Project Outcomes

This project demonstrates practical experience in:

  • Distributed system architecture
  • Microservices-oriented project structuring
  • Containerized backend infrastructure
  • Docker Compose orchestration
  • NoSQL database integration
  • RESTful API engineering
  • JWT authentication workflows
  • Cloud-ready system design concepts

The project also reflects a progression from traditional frontend/backend CRUD applications toward more infrastructure-aware and cloud-oriented full-stack engineering practices.
